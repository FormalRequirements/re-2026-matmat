=== S.2 Functionality

NOTE: Detailed functional requirements classified by the MoSCoW method.

==== S.2.1 Public Module (Visitor Features)

[[S2-1]]
^S.2.{counter:s2}^ **Landing Page**::
[cite_start]The system **MUST** display a landing page presenting the Association 404, its logo, and its core mission ("Mathématiques et Informatique Appliquées aux Sciences Humaines et Sociales")[cite: 43, 74].

[[S2-2]]
^S.2.{counter:s2}^ **Event Agenda**::
The system **MUST** list past and upcoming events in chronological order. [cite_start]Each event card must display a title, date, and short description[cite: 53, 77].

[[S2-3]]
^S.2.{counter:s2}^ **Contact Form**::
The system **MUST** provide a form allowing visitors to send a message to the board. [cite_start]Required fields are: Name, Email, and Message[cite: 61, 79].

[[S2-4]]
^S.2.{counter:s2}^ **Team Directory (Trombinoscope)**::
[cite_start]The system **SHOULD** display the list of current board members, including their full names, roles (e.g., President, Treasurer), and photos[cite: 50, 75].

[[S2-5]]
^S.2.{counter:s2}^ **Projects Showcase**::
[cite_start]The system **SHOULD** include a section to showcase student projects to attract external partners and recruiters[cite: 62, 78].

[[S2-6]]
^S.2.{counter:s2}^ **Dark Mode**::
The system **COULD** allow users to toggle between a light theme and a dark theme for visual comfort (implemented via Tailwind CSS).

==== S.2.2 Administration Module (Back-Office)

[[S2-7]]
^S.2.{counter:s2}^ **Admin Authentication**::
The system **MUST** restrict access to the administration panel. [cite_start]Only users authenticated via Firebase Auth with a whitelisted email address can access it[cite: 187].

[[S2-8]]
^S.2.{counter:s2}^ **Event Management (CRUD)**::
The system **MUST** allow an authenticated administrator to:
* **Create** a new event.
* **Read** the list of all events.
* **Update** an existing event's details.
* **Delete** an event.
[cite_start]This must be done via a GUI without modifying the source code [cite: 27, 64-67].
